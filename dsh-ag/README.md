# dsh-ag

把 **ag中转站** 作为模型供应商接进 **DSH Desktop**
（DeepSeek Harness 桌面版）。**装上就生效，关掉就失效，不需要任何命令。**

- **不保存密钥**：插件只往 `llm-pi-ai` 设置段里写一条供应商路由，用凭据名（默认
  `AG_API_KEY`）引用密钥，密钥始终待在你自己的 DSH 凭据库里。
- **开关就是插件本身**：插件挂载 = 接入；在插件面板里关掉它，它写进去的路由和它装的代理会一起撤掉，
  模型随之从选择器里消失；重新打开就再接回来。
- **不动你原来的东西**：那个路由位置在你装插件之前如果有内容（比如你在「设置 → 模型」里手写过一条），
  插件卸载时会把原来那条原样放回去。

> **名字说明**：包名和目录名是 `dsh-ag`（npm 包名只能用 ASCII 字母），状态命令是 `/ag`；
> 界面、文档和模型卡片里统一显示「ag中转站」。

转发给别人用：看 [INSTALL.zh-CN.md](INSTALL.zh-CN.md)（安装步骤、首次使用、排错、卸载）。

## 使用

1. 装好插件（见 [INSTALL.zh-CN.md](INSTALL.zh-CN.md)），重启一次 DSH Desktop。
2. 打开 **设置 → 模型**，找到 **ag中转站** 卡片，点 **密钥**，粘贴你自己的 API 密钥并保存（只需做一次）。
3. 在模型选择器里选 `glm-5.3` 或 `deepseek-v4-flash`，直接对话。

没有开机 / 关机命令：**插件挂载 = 接入，插件卸载 = 撤掉**。在插件面板里关掉这个插件，或者把它从
profile 的 `dsh.profile.bundles` 里去掉，它写进去的那条路由和它装的代理都会一起撤掉；如果那个
位置本来就有你自己的一条路由，插件卸载时会把原来那条放回去。

会话里随时可以输入 `/ag` 看状态（地址、模型、密钥是否配置、端点是否可达、代理装了
没有）。它只报告，不改动任何东西；带别的参数（比如以前习惯的 `on` / `off`）也只会得到一句
说明和同样的状态。

## 配置

配置在插件目录的 `cordis.patch.yml` 里：

| 字段 | 含义 |
| --- | --- |
| `displayName` | 模型卡片上显示的名字，默认 `ag中转站` |
| `baseURL` | 接口地址，默认 `https://agentrouter.org/v1` |
| `apiKeyEnv` | 凭据名，默认 `AG_API_KEY` |
| `originator` | 请求头 `originator`，默认 `codex_cli_rs`（见下） |
| `proxy` | 本地代理地址，例如 `http://127.0.0.1:7890`；能直连就填 `''` |
| `models` | 暴露给 dsh 的模型 id 列表 |

改完要重启一次 DSH。也可以不改插件本身，而在 profile 自己的 `cordis.patch.yml` 里按 id 覆盖
（这一层在所有插件之后应用，**重装插件不会覆盖它**）：

```yaml
- id: ag
  config:
    baseURL: https://your-endpoint.example/v1
    proxy: ''
```

（这种覆盖会替换整份 `config:`，其余字段回落到插件内置默认值。）

## 端点当前实际可用的模型

`/v1/models` 会列出六个模型，但截至 2026-09-14 实测只有两个能真正出结果：

- 可用：`glm-5.3`、`deepseek-v4-flash`（工具调用、流式都已验证）
- 返回 `402 Budget pool quota has been exhausted`：`gpt-5.6-sol`、`gpt-6-astra`、`claude-opus-4-8`、`claude-opus-5`

402 是账号/额度层面的限制，不是配置问题；额度恢复后这几个会直接可用。想先隐藏它们，
把 `cordis.patch.yml` 里 `models` 列表删掉对应行即可。

## 两个必须知道的细节

**1. 客户端识别头。** ag中转站只放行它认得的编程助手客户端。dsh 会强制发送自己的
`User-Agent` 并且保留这个头，所以路由改用一个 `originator` 头（dsh 会原样透传），插件写入的
路由总是带着它。少了它的表现是：请求被服务端以 401 拒绝，而界面把 401 说成「API 密钥无效」，
很容易误判成密钥问题。插件写入的路由一定带着这个头，所以先确认插件确实在挂载状态即可。

**2. 代理。** ag中转站并不是所有网络都能直连，而 Node **不读取操作系统的代理设置**
（浏览器走了系统代理，命令行程序不会跟着走）。所以当 `proxy` 非空时，插件在运行时把
ag中转站的域名指向该代理 —— 只有这一个域名走代理，其它供应商、`web_fetch`、本机回环
地址都不受影响；插件卸载时会把原来的 dispatcher 原样放回去。

插件用 undici 的全局 dispatcher 实现这一点，因为 `NODE_USE_ENV_PROXY` 是 Node 启动前读取的，
插件在运行时设置它没有任何效果。

## 移除

在插件面板里关掉即可：路由、代理都会撤掉，模型也随之从选择器里消失。

要彻底删除：删掉 profile 的 `node_modules\dsh-ag` 目录，从 `package.json` 的
`dependencies` 和 `dsh.profile.bundles` 里删掉 `dsh-ag`，重启。
